
## 练习 1：case 2 如何切换到 case 3

### 1. 返回 true 的条件
设置的位置x，y，z和实际位置的差值都小于误差（error_max），并且偏转角yaw小于0.1
### 2. local_pos 何时更新、由谁更新
何时更新：在收到/mavros/local_position/odom 并spinonce时候更新
由谁更新：进回调local_pos_cb，在这里更新
### 3. 返回 false 后发生什么
如果这次返回 false，这一轮后面就会break跳出switch，然后继续publish(setpoint_raw)，spinOnce，sleep，之后重新进入while循环，以mission_num =2重新进入switch case2 .直到返回true，mission_num变为3，下一次循环进入case3




## 练习 2：从"去哪里"到"怎样移动"

### 1. 我填哪些字段
- type_mask = 1+2+4+64+128+256+2048 = 2503
  → 忽略位置、加速度、yaw_rate
- coordinate_frame = 1（FRAME_LOCAL_NED）
- velocity.x / y / z（z 恒为 0，表示竖直目标速度为 0）
- yaw = 0

### 2. 怎样从位置算出速度
误差 e = 目标 − 当前（三个轴分别算）
速度 v = k · e，k 取 0.5
（附代码片段：ex/ey/ez、vx/vy 那几行）

### 3. 怎样限速
先算水平合速度 v_norm = sqrt(vx² + vy²)，
若 v_norm > v_max，则 vx、vy 等比缩放：
  vx = vx / v_norm * v_max
理由：分别限制 vx、vy 时，两个轴各 1.0 会让合速度达到 1.41；
等比缩放能保证方向不变、合速度恰好等于 v_max。

### 4. 到达后怎样停止
各轴误差 < err_max 且 |yaw − 0| < 0.1 时，
把 velocity.x/y/z 全部置 0，再返回 true。
因为 cpp 里紧接着会 publish，零速度才真正发到飞控；
若只 return true 而不清零，飞控会继续按上一轮速度飞。

### 5. 放在哪段任务逻辑里
替换 `switch` 中的 `case 2`，把 mission_pos_cruise 换成
mission_velocity_cruise(4.0, 0.0, ALTITUDE, 0.0, err_max, 0.5, 1.0)。
返回值含义不变：true = 这一步完成 → mission_num 推进。

### 6. 预测：如果速度只算一次会怎样
会一直以初始速度飞向目标，飞过头也不减速，
因为不再根据新位置修正误差。P 控制的价值就是"每轮重算"。
实际实验中我把 k 从 0.5 改成 2.0，观察到冲过目标后需要反向修正，
验证了这个判断。
